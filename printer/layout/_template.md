# layout spec テンプレート

配置先: `docs/design/layout/_template.md`
正本: CCLauncher の `printer/layout/_template.md`（直接編集せず、上流を更新して再取得する）

画面パターン1つにつき `docs/design/layout/{pattern}.md` を1ファイル作る。
`{pattern}` はケバブケース（`login` / `search` / `list` / `detail` / `edit` など）。

パターンは「画面の種類」であってページ名ではない。同じ構成原則で説明できる画面は同じパターンにまとめる。

---

## テンプレート本体

````markdown
# list

## 使う場面

同種のアイテムが並び、絞り込み・並べ替え・個別への遷移が発生する画面。
件数が可変で、0件・少数・大量のすべてが起こりうる。

`search` との違い: 検索が主目的（入力が起点）なら search、一覧が主目的（閲覧が起点）なら list。

## 構成原則

上から順に、ユーザーが「絞る → 見る → 選ぶ」の順で視線を落とせる配置にする。
操作結果（件数）は操作の近くに置く。離すと、絞り込みの効果が確認できない。

## 領域分割

| 領域 | 内容 | 備考 |
|---|---|---|
| header | ページタイトル、主要アクション | 主要アクションは1つ |
| filter | 絞り込み・並べ替え、結果件数 | 件数は filter と同じ視野に置く |
| body | アイテムの繰り返し | 0件・読み込み中・エラーの3状態を必ず持つ |
| footer | ページネーション or 追加読み込み | どちらか一方。混在させない |

## 標準的なコンポーネントの組み合わせ

- filter: `FilterChip` の横並び + `Select`（並べ替え）
- body: `Card` のグリッド、または `ListRow` の縦積み。1画面で混在させない
- 0件: `EmptyState`（原因と次のアクションを必ず出す。「該当なし」だけで終わらせない）
- 読み込み中: `Skeleton`（スピナーではなく、確定するレイアウトの形で出す）

## レスポンシブ方針

| 幅 | 挙動 |
|---|---|
| 狭 | filter を折りたたみ、body は1カラム |
| 中 | filter を横並び、body は2カラム |
| 広 | filter を固定表示、body は3カラム以上（可読幅の上限で止める） |

- カラム数の切り替えはコンテナ幅で判断する（ビューポート幅を直接見ない）
- ブレークポイントの値は tokens が持つ。ここに px を書かない
````

## 書くときの担当

| セクション | 人間 | AI |
|---|---|---|
| 使う場面・構成原則 | ○（パターンの定義） | 既存画面からの帰納 |
| 領域分割 | 承認 | ドラフト |
| コンポーネントの組み合わせ | 承認 | ○（ui spec の usage から導出） |
| レスポンシブ方針 | 方針決定 | ○（各パターンへの展開） |

## レビュー観点（AI が機械的に検査する）

- ui spec との整合（存在しないコンポーネントの参照、usage に反する使い方）
- `docs/product/content-list.md` の各ページがどのパターンにも対応していない（漏れ）
- px 直書き・ビューポート幅への直接依存
- 0件・読み込み中・エラーの3状態が定義されているか
